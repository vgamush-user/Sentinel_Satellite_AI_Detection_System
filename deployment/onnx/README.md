# ONNX Export + Quantization Benchmark (Week 5 stretch goal)

Owner: ML Lead + Software/Integration Lead. See `ONNX_QUANTIZATION_REPORT.md`
for the full write-up and results — this file is just the "how to run it."

## What this is

The 6-week plan's tech stack table lists a Week 5 stretch goal: *"Model
compression: ONNX Runtime + dynamic quantization," tying back to the
original deck's onboard/SWaP-constrained claim.* This benchmarks exactly
that against the project's real `src/ml/baseline_xgb.json` model and its
real domain-shift test set (`data/noised/noised_dataset.csv`) — every
number in the report comes from an actual run, not an estimate.

Short version of the finding: ONNX export works and shrinks the model 86%
for free; ONNX Runtime's *quantization* step does not apply to tree
ensembles (verified against ONNX Runtime's own source, not assumed) and is
documented as a real negative result rather than skipped silently; the
compression lever that does work for a tree ensemble — fewer boosting
rounds — is benchmarked instead and shows the model can drop to ~27% of
its round count with zero measured accuracy loss.

## Reproduce

```bash
pip install -r deployment/onnx/requirements.txt
python deployment/onnx/export_and_benchmark.py
```

Writes `model_fp32.onnx` and `benchmark_results.json` (the exact source
data behind every table in `ONNX_QUANTIZATION_REPORT.md`) into this
folder. Takes well under a minute on CPU — no GPU, no Groq key, no network
access needed (everything here is local model export/benchmarking).

## Files

- `export_and_benchmark.py` — the benchmark script (see its own docstring
  for the 5 steps it runs).
- `ONNX_QUANTIZATION_REPORT.md` — the write-up: what was tried, what
  worked, what didn't and why, with sourced citations for the "why."
- `requirements.txt` — only what this benchmark needs (`onnx`,
  `onnxmltools`, `skl2onnx`, `onnxruntime`, `sympy`). Not part of the root
  `requirements.txt` — this is a standalone
  analysis, not a runtime dependency of the live agent pipeline.
- `model_fp32.onnx`, `benchmark_results.json` — generated by running the
  script; regenerate anytime with the command above.

## Relationship to the live pipeline

This benchmark does **not** change what the dashboard/agent pipeline
actually runs — `src/tools/classifier_tool.py` and the real-time detector
(`src/streaming/detector.py`) still load `baseline_xgb.json` via native
XGBoost. Swapping the live
classifier to the ONNX export (or to a reduced-round-count model) is a
real option this benchmark validates, not something applied automatically
— see the "Not currently adopted" note in `ONNX_QUANTIZATION_REPORT.md`
for why that's left as a deliberate ML Lead decision.
