full_pipeline.py drives a CSV simulator, checks for unusual features, and runs the crew on rows that pass. The React manual-analysis view offers another way to use this workflow.

  1. 01 · Replay the CSV

    telemetry_simulator.py reads noised_dataset.csv. The runner takes the row with MsgId=6277, passes its 22 features into the pipeline, and keeps the label for console output.

  2. 02 · Pass the monitor gate

    monitor_tool.py compares features with the nominal baseline. This row crossed the escalation threshold and went to the crew.

  3. 03 · Predict Storage Exhaustion

    classifier_agent.py calls classifier_tool.py. XGBoost gives Storage Exhaustion 51.49%, Normal 28.45%, and Data Injection 20.01%. The agent repeats the tool's winning class and score. The difference from the CSV label originates here.

  4. 04 · Add SPARTA context

    sparta_agent.py uses sparta_tool.py to map the predicted class to a tactic and technique and retrieve a precedent from the knowledge base.

  5. 05 · Look up mitigation

    mitigation_agent.py calls mitigation_tool.py. At 0.5149 confidence, the policy returns log_only. The function returns an action name and rationale data. The report's claim that logging was executed goes beyond this lookup.

  6. 06 · Write the report and print status

    incident_reporter_agent.py uses incident_reporter_tool.py to assemble severity and false-positive risk into a record and write the report. The runner separately assigns FLAGGED_FOR_REVIEW because confidence is below the 0.70 action threshold.

How the Kafka services connect

  1. Publish · telemetry.raw

    producer.py replays CSV rows. inject.py builds the same messages for the CLI and website endpoints. topics.py creates the topics, and config.py supplies shared settings.

  2. Score · telemetry.scored

    detector.py reads raw messages, batches inference, and emits the prediction, probabilities, and latency. It loads the native XGBoost model directly.

  3. Group · incidents

    incident_manager.py tracks evidence per satellite. The intended default rule opens an incident after five same-class attack predictions at confidence ≥0.70 among the last 20 rows. A lone row like row 2 would be below the confidence threshold and supply no evidence.

  4. Analyse · reports

    agent_worker.py consumes incident openings. Live mode calls run_pipeline_for_window() on the strongest trigger row. Cached mode reads demo_cache.json by incident class. Both publish report events.

  5. Persist and display

    recorder.py consumes incident and report events and uses storage.py to write SQLite. server.py reads SQLite history, serves the built React dashboard, and streams Kafka activity over WebSocket.
