From telemetry window to review

  1. MonitorStatistical screening against the nominal baseline.
  2. ClassifierXGBoost predicts a class. The agent presents the model output.
  3. SPARTA AnalystMaps the predicted class to threat context. The mapping does not establish attribution.
  4. MitigationA deterministic policy selects an action from the class and score.
  5. Incident ReporterSummarizes the evidence and review context.

The hosted demo checks the statistical Monitor gate before its manual analysis step. This Kafka dashboard scores replay rows and uses a separate confidence and row-count rule to open incidents.

Why review matters

The reported experiment counted 1,786 Normal windows predicted as Data Injection. A blended Command Flooding and Data Injection case produced a 0.999 confidence score for Data Injection despite ambiguous evidence.

Per-window feature attribution is unavailable in this build. The demo uses simulated telemetry and reports policy outputs for review.
